## 확인 결과와 범위

- `:app:assembleRelease` 성공, `apksigner verify` 성공. 기존 광고 의존성의 Kotlin metadata 경고가 있으나 빌드 실패는 없었다.
- 최종 APK 업데이트 설치 성공. 첫 실행 및 위치 권한 거부 상태에서 운영 URL `https://homecare.designboard.net/`의 지도 타일·기관 유형 선택 화면이 표시됐다.
- 위치 권한을 허용한 뒤 반복 콜드 실행에서도 운영 웹이 표시됐다. 시작 시 테스트 광고 표시와 닫기 후 앱 복귀를 확인했다.
- 현재 운영 웹은 이전 화면이다. 신규 회원 화면/API는 로컬 브라우저와 Wrangler에서 검증했다. 이 APK에서 실계정 SNS 복귀, 기관 증빙 첨부/저장, 시스템 인쇄 전체 과정을 운영 서비스와 연결해 검증한 것으로 보고하지 않는다.
- App Link 운영 인증은 웹 `assetlinks.json` 배포와 실제 Play 앱 서명 인증서 대조 후 다시 확인한다. 현재 파일의 인증서는 확인한 로컬 공통 Release 인증서다.
- 증빙·CSV 전송의 한글 보존 및 취소 처리는 웹에서 검증했다. 실제 문서 공급자의 선택·저장·취소는 운영 연결 후 추가 확인한다.

화면·설치 버전·프로세스 종료·logcat 자료는 무시된 로컬 `app/build/qa/20261120-members/`에 보관한다. 인증 비밀값이나 키 파일은 저장소에 포함하지 않는다. 소스 푸시와 운영 웹/회원 API 배포, Play 업로드·심사·공개는 별도 단계다.

## 기기 검증의 남은 항목

최종 APK의 첫 번째/두 번째 콜드 실행은 각각 1394ms / 1703ms로 시작했고, 지도 타일과 기관 유형 선택 콘텐츠를 확인했다. 세 번째 실행 시도 중 에뮬레이터가 반복적으로 부팅 화면으로 돌아갔다. 로그에는 시스템 초기화 반복과 PID 135/143의 `crash_dump helper failed to exec, or was killed`가 있으며, 일시적으로 Activity 조회도 실패했다. 원인을 앱 충돌이라고 단정하지 않는다.

수집한 앱 로그에서 `FATAL EXCEPTION` 또는 이 패키지의 ANR은 발견하지 못했다. 종료 기록에는 WebView 패키지 자동 업데이트에 따른 종료가 별도로 남아 있다. 에뮬레이터가 불안정해 세 번째 연속 실행·완전한 주요 화면 이동·백그라운드 복귀의 최종 검증을 완료하지 못했다. 안정된 기기에서 이 항목들과 신규 회원 기능의 실제 운영 연결을 확인하기 전에는 Play 배포 검증 완료로 판단하지 않는다.
